* Introduction

org-canvas synchronizes Org Mode files with Canvas LMS. Each course content type has its own Org file, and the package pushes changes to Canvas via its REST API.

The workflow treats Org files as the "source of truth" - you design your course entirely in Org Mode and push changes to Canvas. The package tracks sync state via properties (=CANVAS_ID=, =LAST_SYNCED=) so it knows whether to create new items or update existing ones.

* Getting Started

** Prerequisites

- Emacs 27.1 or later
- Org Mode 9.6 or later
- A Canvas LMS instance with API access
- A Canvas API token (generate from Account > Settings > Approved Integrations)

** Configuration

Create =org-canvas-credentials.el= in your course directory:

#+begin_src elisp
;;; org-canvas-credentials.el --- Canvas API credentials  -*- lexical-binding: t; -*-

(setq org-canvas-api-token "your-canvas-api-token-here")
(setq org-canvas-course-id "12345")  ; Found in your Canvas course URL
(setq org-canvas-base-url "https://your-institution.instructure.com")
(setq org-canvas-directory "/path/to/your/course/")

(provide 'org-canvas-credentials)
;;; org-canvas-credentials.el ends here
#+end_src

*Important*: Add =org-canvas-credentials.el= to =.gitignore= to avoid committing your API token.

** Testing Connection

#+begin_src elisp
M-x org-canvas-test-connection
#+end_src

This prints your course name if the connection is successful.

* Sync Order and Dependencies

** Dependency Graph

Course files can contain links to other course files. For example, an assignment may reference a rubric, an assignment group, or link to a page for instructions. These links are resolved during sync to obtain Canvas IDs.

#+begin_example
assignments.org  -->  rubrics.org
                 -->  assignment-groups.org
                 -->  outcomes.org
                 -->  pages.org
                 -->  files.org

quizzes.org      -->  assignment-groups.org
                 -->  outcomes.org

modules.org      -->  assignments.org
                 -->  quizzes.org
                 -->  discussions.org
                 -->  pages.org
                 -->  files.org
#+end_example

** Sync Tiers

Files are synced in tiers based on their dependencies:

*** Tier 0: No Dependencies

These files have no outgoing links to other course files:

| File                  | Canvas Entity     | Notes                         |
|-----------------------+-------------------+-------------------------------|
| =outcomes.org=          | Learning Outcomes | Groups (L1) and Outcomes (L2) |
| =rubrics.org=           | Rubrics           | Grading rubrics               |
| =assignment-groups.org= | Assignment Groups | Weight categories             |
| =pages.org=             | Wiki Pages        | Course content pages          |
| =files.org=             | Files             | Binary file uploads           |
| =discussions.org=       | Discussions       | Discussion topics             |
| =announcements.org=     | Announcements     | Course announcements          |
| =sections.org=          | Sections          | Course sections               |

*** Tier 1: Depends on Tier 0

| File            | Depends On                                       |
|-----------------+--------------------------------------------------|
| =quizzes.org=     | assignment-groups.org, outcomes.org               |
| =assignments.org= | rubrics.org, assignment-groups.org, outcomes.org |
|                 | pages.org, files.org                             |

*** Tier 1.75: Depends on Tier 0 + 1

| File           | Depends On                     |
|----------------+--------------------------------|
| =sections.org=   | sections (Tier 0), assignments |
| (overrides)    | quizzes (from Tier 1)          |

Per-section date overrides are defined as tables in =assignments.org= and require both sections and assignments to exist first.

*** Tier 2: Depends on Tier 1

| File        | Depends On                                    |
|-------------+-----------------------------------------------|
| =modules.org= | assignments.org, quizzes.org, discussions.org |
|             | pages.org, files.org                          |

** Automatic Sync Order

The =org-canvas-sync= function syncs files in proper dependency order:

1. =outcomes.org= (Tier 0)
2. =rubrics.org= (Tier 0)
3. =assignment-groups.org= (Tier 0) - first pass, without drop rules
4. =sections.org= (Tier 0) - course sections
5. =files.org= (Tier 0)
6. =pages.org= (Tier 0)
7. =discussions.org= (Tier 0)
8. =announcements.org= (Tier 0)
9. =quizzes.org= (Tier 1)
10. =assignments.org= (Tier 1)
11. =assignment-groups.org= (Tier 1.5) - second pass, with drop rules
12. Per-section overrides (Tier 1.75)
13. =modules.org= (Tier 2)

*Note*: Assignment groups are synced twice because Canvas rejects drop rules for groups with no assignments. Per-section overrides require both sections and assignments/quizzes to exist.

** assignments.org

Course assignments with due dates, submission types, and grading options.

*** Structure

- Level 1 headings = Assignments
- Body text = Assignment description (exported to HTML)

*** Properties

| Property           | Type      | Description                                   |
|--------------------+-----------+-----------------------------------------------|
| =POINTS=             | number    | Points possible                               |
| =GRADING_TYPE=       | string    | points, percent, letter_grade, pass_fail, gpa_scale |
| =DUE_AT=             | timestamp | Due date                                      |
| =UNLOCK_AT=          | timestamp | Available from date                           |
| =LOCK_AT=            | timestamp | Available until date                          |
| =SUBMISSION=         | string    | Submission type (see below)                   |
| =ALLOWED_EXTENSIONS= | string    | Comma-separated file extensions (py, txt)     |
| =MAX_ATTEMPTS=       | number    | Max submission attempts (-1 = unlimited)      |
| =GROUP=              | link      | Link to assignment-groups.org heading         |
| =RUBRIC_LINK=        | link      | Link to rubrics.org heading                   |
| =OMIT_FROM_GRADES=   | boolean   | Exclude from grade calculations               |
| =ANONYMOUS_GRADING=  | boolean   | Hide student names during grading             |
| =PEER_REVIEWS=       | boolean   | Enable peer reviews                           |

| =PEER_REVIEW_DUE_AT= | timestamp | Peer review due date                          |

*** Submission Types

| Value              | Description                    |
|--------------------+--------------------------------|
| =online_upload=      | File upload                    |
| =online_text_entry=  | Text box in browser            |
| =online_url=         | URL submission                 |
| =media_recording=    | Audio/video recording          |
| =none=               | No submission (e.g., in-class) |

*** Example

:SUBMISSION: online_upload
:ALLOWED_EXTENSIONS: py
:GROUP: [[file:assignment-groups.org::*Labs][Labs]]
:RUBRIC_LINK: [[file:rubrics.org::*Code Quality Rubric][Code Quality Rubric]]
:END:

Write a Python program that demonstrates basic programming concepts.

,** Requirements
- Create a file named =hello.py=
- Print a greeting message
- Define at least one variable
#+end_src

*** Per-Section Date Overrides

Assignment headings in =assignments.org= can contain an optional =#+NAME: overrides= table with per-section date overrides:

#+begin_src org
,* Lab 1: Introduction to Python
:PROPERTIES:
:POINTS: 100
:END:

Assignment description...

#+NAME: overrides
| Section                                      | Due At                 | Unlock At              | Lock At |
|----------------------------------------------+------------------------+------------------------+---------|
| [[file:sections.org::*Section A][Section A]] | <2026-02-15 Sun 23:59> | <2026-02-01 Sat 00:00> |         |
| [[file:sections.org::*Section B][Section B]] | <2026-02-17 Tue 23:59> | <2026-02-03 Mon 00:00> |         |
#+end_src

Each row links to a section in =sections.org=. The section's =CANVAS_ID= is resolved from that file. Empty date cells are omitted from the override. Overrides are synced after both sections and assignments exist on Canvas.

The override sync uses a reconcile approach: it GETs existing overrides, matches by =course_section_id=, then PUTs (update), POSTs (create), or DELETEs (remove) as needed.

* Link Resolution

Properties like =GROUP= and =RUBRIC_LINK= can contain Org links to headings in other files. During sync, these links are resolved to Canvas IDs.

** Link Format

#+begin_example
:GROUP: [[file:assignment-groups.org::*Labs][Labs]]
:RUBRIC_LINK: [[file:rubrics.org::*Standard Lab Rubric][Standard Lab Rubric]]
#+end_example

** Resolution Process

1. Parse the file path and heading name from the link
2. Open the referenced file
3. Find the heading matching the name
4. Read its =CANVAS_ID= property
5. Use that ID in the API payload

*Important*: Referenced items must be synced before items that reference them. This is why sync order matters.

** Supported Link Properties

| Property       | Source File           | Used In                           |
|----------------+-----------------------+-----------------------------------|
| =GROUP=          | assignment-groups.org | assignments, quizzes, discussions |
| =RUBRIC_LINK=    | rubrics.org           | assignments                       |
| (module items) | various               | modules                           |

* Troubleshooting

** Common Issues

*** "Request failed: Timeout"

The API request timed out. org-canvas has built-in timeout recovery that searches Canvas for recently created items and retries if needed.

*** "CANVAS_ID not found for linked item"

The item being referenced hasn't been synced yet. Run =org-canvas-sync= to sync in proper dependency order, or sync the referenced file first.

*** "API returned 404"

The item exists in your Org file but was deleted from Canvas. org-canvas will automatically retry the operation as a POST (create) instead of PUT (update).

*** "Authentication failed (HTTP 401)"

Your API token has expired or been revoked. Generate a new one at Canvas > Account > Settings > Approved Integrations, and update =org-canvas-credentials.el=.

*** "Permission denied (HTTP 403)"

Your token lacks the required scope. Ensure the token has full access to the course, or generate a new token with broader permissions.

*** "Rate limited after N retries"

Canvas throttles API requests. org-canvas automatically retries on 429 responses, but if the rate limit persists, try reducing the batch size or waiting a few minutes. Configure retry behavior:

| Variable                        | Default | Description                    |
|---------------------------------+---------+--------------------------------|
| =org-canvas-rate-limit-retries=   |       3 | Number of retries on 429/403   |
| =org-canvas-rate-limit-wait=      |      10 | Seconds between retries        |

** Preflight Check

When running =org-canvas-sync=, a preflight check runs automatically before any content is synced. It validates:

1. =org-canvas-api-token= is set and non-empty
2. =org-canvas-course-id= is set and non-empty
3. The API connection works (fetches course name)

If any check fails, the sync aborts with an actionable error message before any API calls are made. Individual sync commands (e.g., =org-canvas-sync-pages=) do not run the preflight check.

** Logging

Logging destination is controlled by =org-canvas-log-destination=:

| Destination | Description                                        |
|-------------+----------------------------------------------------|
| =buffer=      | Log to =*canvas-log*= buffer (default)               |
| =file=        | Log to file (=org-canvas.log= in course directory)   |

Change settings interactively:

#+begin_src elisp
M-x org-canvas-set-log-level        ;; trace, debug, info, warning, error
M-x org-canvas-set-log-destination  ;; buffer, file, both
M-x org-canvas-clear-log            ;; Clear log buffer and file

Additional logging variables:

| Variable                        | Description                      |

* Architecture

** Module Structure

#+begin_example
lisp/
├── org-canvas.el             ; Main entry point, orchestrates all modules
├── org-canvas-core.el        ; Shared infrastructure
├── org-canvas-credentials.el ; API credentials (not in git)
└── org-canvas-{feature}.el   ; Feature modules
#+end_example

** 4-Stage Pipeline

Every feature module follows this pattern:

1. *Parse* - Extract data from Org heading properties
2. *Build Payload* - Convert to Canvas API format
3. *Execute* - Call API with error handling
4. *Finalize* - Save CANVAS_ID and LAST_SYNCED

** Sync State

Items are tracked via the =CANVAS_ID= property:
- Present: UPDATE (PUT) operation
- Absent: CREATE (POST) operation

After successful sync, =LAST_SYNCED= is updated with the current timestamp.
