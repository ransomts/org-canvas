#+TITLE: Design Decisions and Issue Post-Mortems
#+AUTHOR: org-canvas
#+STARTUP: showall

Each heading below records a decision org-canvas made in response to a
concrete failure on a live course, with the issue number, the functions
involved, and the "do not do X" that follows.  They were relocated from
CLAUDE.md (issue #139) so the guide could stay short; nothing was
condensed.  Read the heading whose subject you are about to touch before
changing it -- most of these were expensive to learn.

Related narratives live where their mechanism is documented:

- =design.org= -- pipeline macros, the registry's property specs (=:remote-fn=,
  =:compare-p=), global sync summary, complexity patterns, key lessons
- =api-interaction.org= -- HTTP transport and the PATCH fallback, error
  handling rules, conflict baseline rules, duplicate-title guard, dry-run
  obligations, file re-upload tiers, feature registry URL resolution
- =pull-system.org= -- single-item pull, =:skip-fn= reporting
- =testing.org= -- test isolation, Emacs version matrix, JUnit and
  Codecov, Eldev layout, debugging techniques

The log is split by subject into =decisions/= so that a new section is
appended to a file of its subject's size, not to a file that grows
forever.  This file is the index: every section title is listed below
with a link to the file that holds it, so a cross-reference elsewhere in
the documentation -- =decisions.org, "A Body Never Introduces a
Headline"= -- still names something you can find here.
