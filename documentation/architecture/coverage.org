#+TITLE: What org-canvas Covers, and What It Does Not
#+AUTHOR: org-canvas
#+STARTUP: showall

This is the map of the gap between Canvas and org-canvas: which parts
of a Canvas course the package manages, which it only reads, and which
it never touches.  It exists so the answer to "does org-canvas do X?"
is a lookup, not an archaeology of =lisp/=.

It was built by grepping =lisp/= for each Canvas API surface a course
uses and reading what the hit does; it describes the code as of the
commit that last edited this file, and the last section says how to
refresh it.  A gap listed here is a fact, not a promise: an item moves
to the covered table when a module lands, and nothing here is a
roadmap.

* Covered Content Types

One module per type.  "Push" is =org-canvas-sync-{type}=; "at point"
is the single-heading push every =org-canvas-define-sync= generates
unless it opts out; "pull" is =org-canvas-pull-{type}=; "delete" is
=org-canvas-delete-all-{type}= together with the prune command it
generates; "registry" means the type is in the feature registry, which
is what gives it the drift report, the duplicate-title guard,
pull-at-point and prune.

Submission grading (=org-canvas-submissions.el=) is a workflow, not a
content type: it pulls a grading file per assignment, pushes scores
and comments, posts grades held by a manual policy, downloads
attachments, and reads and pushes each student's rubric assessment
through the grading file's Rubric table.

*Course settings synced* (the registry in =org-canvas-settings.el= is
the authority): the syllabus body, whether it is public, the home page
view, licence, start and end dates, the student discussion and
announcement permissions, past and future view restrictions, the
announcements-on-home setting and its limit, distribution graphs,
final-grade hiding, weighted assignment groups, the grading standard
by id, the late and missing submission policies, the course image,
and the grade post policy.  Navigation tabs are synced from the
settings file.

* Touched in One Direction, or by Reference Only

| Feature                        | What org-canvas does                                   | What it does not do                          |
|--------------------------------+--------------------------------------------------------+----------------------------------------------|
| Groups                         | a category can ask Canvas to create N groups; groups and their members are pulled; an assignment override can name a group | name groups or manage members from Org |
| Quiz question banks            | a classic quiz group may name a bank on create (PUT ignores it) | create, list or edit a bank: there is no API, see "No API" below |
| Rubric assessments             | read and pushed per student from the grading file's Rubric table, the total setting the grade when the rubric is used for grading; the class's per-criterion results are pulled (see the covered table) | assess from Org outside the grading file; clear an assessment (SpeedGrader's) |
| External tools (LTI)           | list installed tools so an assignment can name one     | install or configure a tool                  |
| Turnitin document processor    | pull and diff the attachment as a Canvas-owned property | set it; deliberately, see decisions.org      |
| Planner                        | a page's student to-do date                            | planner notes or the to-do list              |
| Submissions                    | grades, comments, attachments, posting grades and each student's posted-at, per assignment; the course-wide score overview (gradebook.org); a classic quiz's attempts, kept and latest scores and time spent, read-only per quiz; each classic quiz's item analysis (quiz-results.org); who reviews whom on an assignment and which reviews are done, read-only per assignment | New Quiz attempts and reports, assigning peer reviewers, moderation |

* Never Touched

Nothing in =lisp/= reads or writes these.  Where a course needs them,
they are set in the Canvas web UI and org-canvas neither sees nor
disturbs them.

- *Gradebook configuration:* the gradebook's own settings.  Custom
  gradebook columns are pulled into the overview, grading periods are
  pulled and post policies are managed (see the covered table);
  creating a custom column is the web UI's business.
- *Enrolling and removing people.*  The roster and section
  membership are pulled (see the covered table); changing them is the
  registrar's and the web UI's business.
- *Mastery Paths* (conditional release), *Blueprint* associations and
  locks, and course-level *feature flags*.
- *Collaborations*, *conferences*, *appointment groups* (the scheduler),
  *chat*, *attendance*.  The Inbox is written to (see Conversations in
  the covered table) but never read: replies stay in the web UI.
- *Outcome alignments* as objects and the *learning mastery gradebook*;
  outcomes themselves are covered.
- *Content migrations, course copy, exports and ePub.*  org-canvas is the
  copy mechanism: a course is rebuilt from its Org files.
- *Media* (Canvas Studio, media objects); a file is a file.
- *Account-level* objects of every kind: terms, sub-accounts,
  developer keys, SIS.

* No API

Probed read-only on 2026-09-11 against clemson.instructure.com, so
nobody has to probe again:

- *Classic question banks.*  =GET /api/v1/courses/:id/question_banks=
  is a 404.  The web UI's =/courses/:id/question_banks= answers a token
  with the HTML page, and its =.json= form with a 401: it wants a
  browser session, not an API token.  A bank is created in the web UI
  or by a QTI import, and a classic quiz group names it by the id in
  the UI's URL, on create only (Canvas ignores
  =assessment_question_bank_id= on update).
- *New Quiz item banks.*  The New Quizzes API (=/api/quiz/v1/=, which
  answers the course's quiz list) has no bank route:
  =courses/:id/item_banks=, =courses/:id/banks= and =/banks= are all
  404.  Items live inline under the quiz in new-quizzes.org, which is
  the whole of what the API offers.

* Deliberately Excluded

- *Turnitin* as a plugin (=TURNITIN_ENABLED=) was removed after a live
  probe found it inert, and the LTI document-processor mode can only
  be attached in a browser; org-canvas observes and protects it.  Hard
  Rule 5 and decisions.org, "External-Tool (LTI) Assignments — and No
  Turnitin".
- *Payload format convergence* between hash tables and alists, because
  it would rotate every stored hash.  design.org, "Why the Formats Are
  Not Converged".

* Which Gaps Bite, and the Decision to Stop

The four absences that ranked here when this map was first written —
posting policies, group membership, grading periods and discussion
replies — are closed, and the three rounds of 2026-09-10 and 11 (#210
to #247) added the roster, the gradebook overview with its assignment
spread and custom columns, rubric and quiz results, quiz attempts,
peer reviews, grading schemes, student and group overrides, quiz
accommodations, checkpoints and messages.

*On 2026-09-11 the decision was to stop chasing parity with the Canvas
web UI.*  What follows is the list of what was left, ranked, so that
when one of them bites a course run from Org the scoping is already
done.  Add the incident beside the item when it happens; do not build
an item because it is on the list.

** Left Undone, Ranked

1. *Assigning peer reviewers.*  Who reviews whom is read
   (=org-canvas-pull-peer-reviews=); assigning or removing a reviewer is
   the web UI's.  The routes exist per submission
   (=POST/DELETE .../submissions/:id/peer_reviews?user_id=), so a table
   in the peer-reviews file could be reconciled as the overrides table
   is.  Matters only for reviews assigned by hand rather than
   automatically.
2. *Group management from Org.*  Groups, members, override rows and
   message targets resolve through groups.org; creating a group or
   moving a student is the web UI's.  Membership hangs under another
   type's heading and needs the child-reconciler pattern modules,
   quizzes and New Quizzes use.  The hardest item here.
3. *Grade change history.*  Never read.  One read-only endpoint
   (=courses/:id/gradebook_history/...=); useful in a dispute, rarely
   otherwise.
4. *Rubric assessment outside the grading file.*  Per-student rubric
   scores are typed in the grading file and nowhere else; arguably the
   right design.
5. *Planner notes and the to-do list*, beyond a page's student to-do
   date.

** Closed by Canvas, Not by Us

- Question banks and New Quiz item banks: no API (see "No API").
- New Quiz attempts and reports: no submissions or statistics endpoint
  in the public API.
- A bank-backed quiz group: the pull learns of a group only through
  the questions that name it, so a group drawing solely from a bank is
  invisible to the pull.
- Discussion checkpoints are built but the account flag is off at
  clemson.instructure.com, so the push has only been exercised by
  mocks.

** Watch on First Live Use

Three write paths added in these rounds have never been sent to a
live course, because the course at hand had nothing to exercise them:
the grading scheme create (#213), the checkpoint mutation (#216), and
a sync of a quiz with question groups after a pull (#243).  Read the
log the first time each runs for real.

What remains in "Never Touched" is rarely set at the course level or
belongs to the institution; nothing there is known to have bitten a
course run from Org.

* Adding a Type

A flat object with no children is the simplest candidate: a pull-only
module is a registration, a =define-pull= and a test file, and a full
sync adds parse, build and =define-sync= on top (grading periods went
exactly that way; post policies needed GraphQL, see decisions.org).  =module-developer-guide.org= is the step by
step.  Managing membership from Org would be harder, because members hang
under another type's heading and need the child-reconciler pattern
modules, quizzes and New Quizzes use inside finalize; reading them, as
replies are read, took the pull-only route.

* Refreshing This Document

The map came from one loop over API surface names against =lisp/=:

#+begin_src sh
for pat in grading_period "post_polic|post_manually" enrollments \
           "api/v1/groups" discussion_entries setCheckpoints mastery_path blueprint \
           collaboration conference appointment_group feature_flag \
           question_bank item_bank conversations; do
  printf "%-28s %s\n" "$pat" "$(grep -rlE "$pat" lisp/*.el | tr '\n' ' ')"
done
#+end_src

An empty right-hand column is a "never touched"; a hit is a claim to
read before moving the line.  The names in the loop are the ones this
map was first drawn against; several now hit, which is the point of
rerunning it, and a surface that stops hitting has been removed.  When a module lands, move its type into
the covered table and drop it from wherever it sat.  Counts stay out of
this file (Hard Rule 21); it names things, it does not tally them.
